# VPSChecker

[English version](README.md)

VPSChecker — терминальная утилита для оценки пригодности IP-адреса VPS в качестве
выходной VPN-ноды. Она проверяет репутацию IP, доступность сервера из выбранной
страны, а также локальную и внешнюю доступность TCP-порта VLESS и UDP-порта
Hysteria2. По умолчанию проверки выполняются из России.

После успешного запуска утилита формирует текстовый и JSON-отчёты с отдельными
результатами проверок, общей оценкой пригодности IP для VPN и рекомендацией о том,
есть ли основания запрашивать у хостера замену адреса. Проверки выполняются с
минимальными изменениями системы.

## Требования

- Debian или Ubuntu;
- Bash 5.1 или новее;
- подключение к интернету по IPv4.

## Использование

Запуск с автоматическим определением внешнего IPv4 и стандартными портами:

```bash
./vps-check.sh
```

По умолчанию целевая страна — Россия (`ru`), а для VLESS и Hysteria2 проверяются
TCP/443 и UDP/443 соответственно. Страна задаётся двухбуквенным кодом ISO. IP,
страну и порты можно переопределить:

```bash
./vps-check.sh --ip 203.0.113.10 --country de --vless-port 2053 \
  --hysteria2-port 8443 --report-dir reports/de
```

`--ip` можно не указывать: утилита определит внешний IPv4 через HTTPS. Явное
значение позволяет пропустить отдельный запрос для автоопределения адреса.

Чтобы дополнительно вывести текстовый отчёт в терминал, не отключая сохранение
обоих файлов:

```bash
./vps-check.sh --print-report
```

Посмотреть установленную версию:

```bash
./vps-check.sh --version
```

Автоматически выполнить накопленный план очистки после проверок:

```bash
./vps-check.sh --cleanup
```

Без флага можно позднее выполнить выведенную подсказку из того же каталога:

```bash
./vps-check.sh cleanup
```

Отдельная команда показывает точный список пакетов и запрашивает подтверждение.

Посмотреть справку по командам и параметрам:

```bash
./vps-check.sh --help
```

Посмотреть доступные в Check-Host коды стран, количество узлов и города:

```bash
./vps-check.sh list-locations
```

## Отчёты

После успешной проверки в `./reports` относительно текущего каталога создаются
два файла с правами `0600`:

- `reports/vpschecker-report-<UTC timestamp>-<PID>.json`;
- `reports/vpschecker-report-<UTC timestamp>-<PID>.txt`.

Каталог создаётся только перед непосредственным формированием отчётов. Другой
относительный или абсолютный путь можно задать через `--report-dir`; права уже
существующего каталога не изменяются:

```bash
./vps-check.sh --report-dir /var/lib/vpschecker/reports
```

JSON имеет стабильные разделы для репутации, пригодности IP для VPN, рекомендации
о замене, региональной доступности, портов, протокольных проверок и очистки. В него
также без изменений включается исходный результат IPQuality. Рекомендация о замене
принимает значение `REPLACEMENT_JUSTIFIED`, `REPLACEMENT_MAY_HELP`,
`REPLACEMENT_UNLIKELY` или `INCONCLUSIVE` и содержит причины и подтверждающие
факты. Итоговые отчёты сохраняются, а временные файлы удаляются при выходе. В
разделе очистки указывается, были ли добавленные пакеты отложены, удалены,
отсутствовали, оставлены из соображений безопасности или не смогли удалиться.

## Временные файлы

Файлы текущего запуска создаются в `${TMPDIR}`, а если переменная не задана — в
`/tmp`. Исходник и рабочая копия IPQuality, исходный JSON, диагностический журнал,
результат оценки и ответы Check-Host хранятся в каталоге `vpschecker.XXXXXX`.
Журнал изменений APT создаётся отдельно в `vpschecker-deps.XXXXXX`. Оба каталога
удаляются при обычном завершении и обработанных сигналах остановки.

`.vpschecker-cleanup.plan` не является временным runtime-файлом и сохраняется до
успешного удаления записанных в нём пакетов.

## Версионирование

Файл `VERSION` — единственный источник версии инструмента. VPSChecker использует
семантическое версионирование, показывает версию через `--version` и добавляет её
в текстовый и JSON-отчёты. Релизу должен соответствовать Git-тег `v<версия>`,
например `v0.1.0`; после этого его можно опубликовать как GitHub Release.

## Обновление IPQuality

Проверить и обновить закреплённую версию IPQuality:

```bash
./scripts/update-ipquality.sh
```

Можно проверить конкретный полный commit SHA:

```bash
./scripts/update-ipquality.sh COMMIT_SHA
```

Скрипт проверяет текущий исходный файл, загружает кандидата, показывает его
checksum и diff, после чего запрашивает подтверждение перед изменением фиксации.

## Внешние сервисы

VPSChecker автоматически использует:

- [xykt/IPQuality](https://github.com/xykt/IPQuality) — загружается по
  закреплённому commit и собирает данные о репутации и геолокации IP. IPQuality
  обращается к собственным внешним источникам данных; privacy mode запрещает
  публикацию ссылки на его онлайн-отчёт, но не переводит проверку в офлайн-режим.
- [Check-Host API](https://check-host.net/about/api?lang=en) — предоставляет
  актуальный список узлов и выполняет региональные ping-, TCP- и UDP-проверки.
- [ipify](https://www.ipify.org/) — определяет внешний IPv4 через
  `https://api.ipify.org`, только если не указан параметр `--ip`.

При результатах `WARNING` и `POOR` в отчёт добавляются ссылки для ручной
перепроверки через [AbuseIPDB](https://www.abuseipdb.com/),
[Scamalytics](https://www.scamalytics.com/),
[IPQualityScore](https://www.ipqualityscore.com/free-ip-lookup-proxy-vpn-test/),
[VirusTotal](https://www.virustotal.com/gui/home/search) и
[Cisco Talos Reputation Center](https://talosintelligence.com/reputation_center/).
VPSChecker не обращается к этим страницам только ради формирования ссылок. При
этом некоторые из сервисов могут использоваться самим IPQuality как источники
данных.

## Как работают проверки

Репутация, региональная доступность и состояние сервисов оцениваются и отражаются
в отчёте раздельно. IPQuality загружается из закреплённого commit с проверкой
SHA-256 и запускается для IPv4 в режимах JSON и privacy mode. Его установщик
зависимостей отключён, а успешный исходный JSON сохраняется без изменений. На его
основе VPSChecker формирует оценку пригодности IP для VPN: `OK`, `WARNING`, `POOR`
или `UNKNOWN`, с конкретными причинами. Признаки хостинга и почтовая репутация на
эту оценку не влияют.

Для региональной проверки VPSChecker получает актуальный список узлов Check-Host
и выбирает до трёх узлов в указанной стране и трёх контрольных узлов в других
странах. Через них выполняются вспомогательный ping, TCP-проверка порта VLESS и
UDP-проверка порта Hysteria2. Результат UDP обозначается как `OPEN_OR_FILTERED` и
не считается подтверждением работоспособности протокола.

Read-only preflight определяет ОС, текущие права, внешний IPv4, наличие нужных
команд и APT-пакетов, а также локальные TCP/UDP listeners. Он не устанавливает
пакеты и не вызывает `sudo`.

Если отсутствуют необходимые APT-пакеты, VPSChecker показывает их список и
запрашивает подтверждение. После подтверждения выполняется `apt-get update`,
затем устанавливаются отсутствующие пакеты без рекомендаций. Общий `upgrade` и
`autoremove` не запускаются.

По умолчанию добавленные VPSChecker пакеты сохраняются и записываются в файл
`.vpschecker-cleanup.plan` в текущем каталоге. В терминал выводится команда, которой
их можно удалить позднее. Флаг `--cleanup` запускает очистку автоматически при
выходе. Ранее установленные пакеты и обновлённые при установке версии сохраняются
в обоих режимах.

Перед удалением всегда выполняется симуляция APT. Очистка продолжается, только если
она не затрагивает пакеты вне сохранённого списка. `autoremove` не используется.
